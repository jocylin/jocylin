01 · The Kernel Boundary

三次重写，每一次都因租户更不可信

每一代虚拟化的跃迁，都是把"共享什么"和"隔离什么"的边界重画一次。驱动力始终一样：新租户的可信度下降。裸机时代你信任全部代码；容器时代你信任自己写的代码；agent 时代，代码是 LLM 现写的，你一行没读过。

Docker 一位工程师在 2026 年 5 月写道："我在二十年里看着这个行业重建了三次信任模型。"共享 kernel 在容器时代没问题，因为威胁是你自己软件里的 bug，不是你刚请进门的租户带来的意外。他对结局的预判是：microVM 的争论会重走同一条弧线——争论大约一年，三年内成为常识。
内核边界三次上移：裸机 → 虚拟机 → 容器 → Sandbox
02 · The Isolation Frontier

性能的来源，永远是少做隔离工作

"做更轻的方案该砍哪层隔离"没有标准答案，只有一条连续光谱：每砍一层，换来更快的冷启动和更高的密度,但逃逸所需的漏洞类别也少一类。行业据此分裂成三种赌注,差异不在好坏,而在威胁模型与负载形态是否匹配。

05 · Company Snapshot

Smolmachines / smolvm：一个更底层的 portable microVM primitive

Smolmachines 的核心不是再做一个 cloud sandbox API，而是把微型虚拟机变成开发者可以本地运行、云端部署、单文件携带的 runtime primitive。对 AI agent 来说，它解决的是同一个问题：模型生成的代码越来越不可信，但执行环境仍需要足够快、可复制、可迁移。

4.1k+smolvm GitHub stars，早期开发者关注度已经跑出来
<200ms公开 README / demo 主打的 cold-start 量级
VM-level相对 container sandbox，强调 kernel / VM 级隔离边界
$35M公司沟通中提到的本轮 cap；仍需最终文件确认

一句话定位

Smolmachines 试图把软件、依赖和运行状态打包成可移植的 .smolmachine，让 agent / developer workload 可以在本地、云端或自部署环境中用同一套 VM artifact 运行。

为什么现在重要

AI agent 会频繁执行用户没读过、模型即时生成的代码。传统 container 共享 host kernel，安全边界不够硬；传统 VM 又太重。Smolmachines 押注的是：agent 时代需要一个介于 Docker 易用性和 Firecracker 隔离性之间的新 runtime。

产品 wedge

  • 开源 smolvm CLI，跨 macOS / Linux / Windows。
  • 本地可调试，云端可部署，适合开发者工作流。
  • 单文件状态打包、OCI 镜像启动、网络白名单、SSH agent 转发。
  • 更适合短生命周期、可 fork、需要隔离的 agent workload。

早期 traction

  • 开源项目已有 4.1k+ stars 和 188 forks。
  • 公司沟通中提到已有商业化 usage，客户每天启动几千个 VM。
  • 客户与收入口径仍偏早期，ARR、留存、gross margin、事故率都需要进一步验证。

投资判断：小额 access / portfolio adoption option，值得继续验证

这不是一个已经被数据证明的 growth deal，而是一个底层 infra call option。赛道 beta 来自 agent sandbox 需求真实增长；公司 alpha 来自“portable VM as container replacement”的开发者心智。如果它能从 demo 速度走到 production trust，早期估值下有不对称性；如果做不到，就容易被 E2B、Daytona、Modal、Vercel、Cloudflare 或 AWS 变成一个 feature。

我们看好的三点

  1. 边界重画：agent workload 把安全边界从 container 拉回 VM / microVM。
  2. 开发者 primitive：Smolmachines 不是只卖 API，而是在争取成为本地 + 云端一致的 VM artifact layer。
  3. 开源分发：早期 stars 说明开发者对 portable microVM 有真实兴趣，这比纯 sales-led infra 更容易形成 mindshare。

需要警惕的三点

  1. production trust：底层 runtime 最难的是让客户敢跑真实 workload。
  2. 单点团队风险：YC 页面显示 team size 1，而产品横跨 hypervisor、kernel、networking、storage 和 cloud ops。
  3. 商业化未验证：目前还缺付费客户数、ARR、留存、gross margin、平均 VM 生命周期和 failure rate。

竞争位置

Smolmachines 的差异点在于“更底层、更本地、更可移植”；短板在于生产信任、客户规模和团队厚度仍早。

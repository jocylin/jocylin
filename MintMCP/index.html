Executive takeaway

这不是再买一个 Copilot，而是补上 AI 时代的 access layer：模型会变，权限、凭证和审计不能继续散落在员工设备里。

01 Why now

员工采用 AI 的速度，已经快于企业治理体系。

问题不是员工会不会使用 AI，而是安全团队能不能回答：谁在用、能调用什么、是否可撤销，以及出了问题能否完整追溯。

01 /

看不见

个人 OAuth、API Key 与本地 MCP 形成 Shadow AI，安全团队缺少统一视图。

02 /

权限过大

Agent 继承人的广泛权限，但一次任务实际需要的 scope 往往小得多。

03 /

管不到动作

能看到使用情况，不代表能在执行前关闭危险工具或阻断高风险调用。

04 /

事故难追溯

系统分散后，很难还原哪个人、哪个 Agent、通过哪个工具访问了什么。

02 Product system

一个负责 control，一个负责 adoption。

Gateway 把风险和权限收进可治理路径；Coworker Agents 把受控 Agent 放进团队已经使用的 Slack 工作流。

Control01

MCP Gateway

统一管理所有 AI 工具与企业系统之间的连接，按角色、Agent 和单个 tool 执行 least-privilege policy。

→Approved MCP registry 与 role-based bundles
→Agent identities、delegated credentials 与独立撤销
→Prompt injection、PII、secret scanning 与 custom middleware
→调用监控、成本视图、audit log 与 SIEM / OTLP export
→SSO、DLP、MDM enforcement 与 private tunnel
经 Gateway 路由的调用，可归因到人、Agent、server、model 与具体工具。
Adoption02

Coworker Agents

把 Agent 放进 Slack 频道与 thread，让工作流可被团队共享、复用和监督，而不是留在个人聊天框。

→人在同一 thread 中审阅、补充与接管
→工作流对团队可见，不依赖个人 prompt history
→支持 scheduled 与 proactive workflows
→工具调用统一经过 MintMCP Gateway 控制
→可从 read-only 场景开始，按审批逐步扩大 scope
Gateway 解决 control；Coworker Agents 解决 adoption。
03 Architecture

一条受控路径，连接所有 Agent 与内部系统。

不要求先押注某一个模型，也不把权限写死在某一个客户端。可通过现有 MCP server、REST API、connector 与 private tunnel 评估接入。

05 Decision checklist

交易所决策者真正需要问的五个问题。

不是“支持多少模型”，而是身份是否独立、权限是否可撤销、动作是否可控制、事件是否可追溯。

01

谁执行了动作？

经 Gateway 路由的调用可追溯到人、Agent、server、model 与具体工具。

02

权限能否独立撤销？

每个 Agent 可配置独立身份、scope 与 delegated credentials，不必共享人的全部权限。

03

危险动作能否提前关闭？

按单个 tool 执行授权与 policy；高风险写操作可在批准前保持禁用。

04

能否接入现有安全栈？

官方公开能力包括 SSO、DLP、SIEM / OTLP、MDM enforcement、middleware 与 private tunnel。

05

是否等于自动满足监管？

不等于。MintMCP 提供治理控制与审计证据，最终合规判断和责任仍由交易所承担。

06 Low-risk pilot

不要从全公司 rollout 开始。

先选一个真实工作流，在边界内同时验证安全、可用性与业务价值。建议由业务 owner 与 Security 共同定义成功标准。

WEEK 0 / SCOPE

选一个场景

确认数据源、用户组、允许的 read tools，以及明确禁止的写操作。

WEEK 1–2 / BUILD

接入与设防

配置身份、权限、approved MCP、guardrails、logging 与 rollback plan。

WEEK 3–4 / VERIFY

小范围验证

复盘调用记录、阻断结果、用户反馈与效率指标，再决定是否扩大。

Security acceptance

未授权 tool 被阻断；调用可归因；权限可撤销；日志满足内部复核。

Business acceptance

目标工作流产生可量化改善；员工真实采用；业务与 Security 共同批准下一阶段。
